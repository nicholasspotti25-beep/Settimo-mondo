# Work logs

One file per work-stream (`<stream>.md`), kept by that stream's lead. Work happens in bounded chunks that can be interrupted
(usage limits), so each chunk starts by reading its log and ends (and updates after every finished deliverable) by writing it.

Each log has three sections:

- **Status** — every deliverable of `docs/briefs/<stream>.md`, marked `done` / `partial` / `missing`, with the files involved.
- **Next** — the ordered list of what to do next (the next chunk starts at the top).
- **Notes** — verification evidence of finished work, decisions, known issues, requests sent to other streams.
